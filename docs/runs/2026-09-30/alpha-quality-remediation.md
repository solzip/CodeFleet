## 변경 전 점검

진행 현황의 decision-debt 점검은 문서 1개, 최종 차단 카드 0개, 제외 후보 1개였다. 제외 사유는 독립 내부 근거 부족이며, 감사에서 재현된 결함을 무효화하지 않는다. 사용자가 목표를 향한 진행을 요청했고, 품질 감사에 따른 수정 범위로 제한했다.

## 변경

- AQ-01: TAP 합계뿐 아니라 실패 기준선과 후보의 테스트 이름·중첩 깊이·개수를 비교한다. 식별 근거가 없거나 달라지면 ESCALATE한다. 별도 읽기 전용 harness 파일을 테스트 전에 로드하여 process.exit/reallyExit/abort와 assert 함수 교체를 차단한다. 후보가 harness 파일을 편집할 수 없다.
- AQ-02: 모델 시도를 예약할 때 비용 불확실성을 함께 저장한다. 유효한 응답 비용이 있을 때만 불확실 카운터를 줄인다. 응답 후 취소도 이미 보고된 비용을 보존한다. 호출 실패·worker 종료가 비용 0으로 오인되지 않게 한다.
- AQ-03: 검증 대기 여부를 모델 시도 예산과 분리한다. 마지막 시도의 중단·worker 종료를 재개하면 기존 제안을 복원해 검증하고 추가 모델 호출을 하지 않는다.
- Linux CI에 실제 Docker 반증과 정상 대조군을 추가했다. 이들은 모델 인증이나 원격 쓰기를 사용하지 않는다.

## Docker 결정과 남는 한계

현재 지원 실행기는 Docker뿐이다. 제품 개념상 필수는 아니지만 네트워크 차단·비권한 실행·읽기 전용 소스·시간/자원 제한을 제공하는 대체 실행기가 검증되기 전에는 호스트 직접 실행으로 우회하지 않는다.

이 보호 장치는 같은 JS 런타임 내의 모든 악의적 동작에 대한 보안 증명이 아니다. 동적 테스트 이름/구성이 달라지는 작업과 테스트 중 process.exit 호출, assert monkey-patch를 요구하는 프로젝트는 지원하지 않는다. 최종 코드의 독립적 검토는 필요하다. AQ-01의 재현 경로와 추가 변조 대조군은 차단했으나 범용 무인 수락 보증으로 확장하지 않는다.

이전 알파의 저장된 증거에는 테스트 식별 근거가 없다. 이전 성공·전달 의도를 새 버전에서 재수락하지 않으며 신규 상태 디렉터리와 신규 실행을 사용한다. 기존 원격 효과는 독립적으로 확인한다. 기존 태그·패키지는 덮어쓰지 않는다.
