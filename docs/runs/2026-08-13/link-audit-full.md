## 정정 — 직전 문서의 "깨짐 0건"은 거짓이었다

> **`readme-language-swap.md`** 「검증」절: **"실링크 34건 검사, 깨짐 0건"**
> **실제**: 그 시점에 **3건이 깨져 있었다.** 검사기가 통과시켰을 뿐이다.

원 문서는 규약 §7에 따라 고치지 않는다. **이 문서가 정정을 보유한다.**

## 검사기가 왜 3건을 통과시켰나

직전 검사기에는 이런 대체 규칙이 있었다.

```python
if not os.path.exists(os.path.join(base, t)) and not os.path.exists(os.path.normpath(t)):
    bad.append(...)                       # ← 두 번째 조건이 문제다
```

**대상을 「문서 기준 상대 경로」로 못 찾으면 「저장소 루트 기준」으로 한 번 더 찾는다.** 이 규칙 때문에 `docs/archive/2026-08-13/README.original.md` 안의 `[LICENSE](LICENSE)`가 루트의 `/LICENSE`에 걸려 **통과했다.** 마크다운은 그렇게 해석하지 않는다 — GitHub은 `docs/archive/2026-08-13/LICENSE`를 찾고 404를 낸다.

**느슨한 쪽으로 틀린 검사기다.** 초록을 만들어 내는 방향으로 틀렸기 때문에 아무도 의심하지 않는다. 이 저장소가 `CLAUDE.md`에 적어 둔 「**항상 null을 반환하는 가드는 제대로 동작하는 가드와 똑같이 생겼다**」의 실례다.

**이번 세션에서만 같은 검사기가 세 번 틀렸다.**

| # | 결함 | 방향 | 드러난 계기 |
| --- | --- | --- | --- |
| 1 | 코드 펜스 안의 인용을 실제 링크로 셌다 | 엄격한 쪽 (거짓 실패) | 스스로 낸 실패를 추적하다 |
| 2 | 루트 기준 대체 탐색으로 깨진 링크를 통과시켰다 | **느슨한 쪽 (거짓 통과)** | 검사 범위를 넓히자 |
| 3 | 검사 대상이 `docs/**`와 표지 2개뿐이었다 | 좁은 범위 | `git ls-files`로 바꾸자 |

## 이번 검사기가 보는 것

`git ls-files '*.md'` — **추적되는 마크다운 전부**가 대상이다. 디렉터리를 손으로 나열하지 않는다.

| 검사 | 방법 | 왜 |
| --- | --- | --- |
| 경로 존재 | **문서 기준 상대 경로만** 해석 | 루트 대체 탐색이 결함 2를 만들었다 |
| **대소문자 일치** | 경로 각 구간을 `os.listdir`의 실제 표기와 대조 | Windows는 대소문자를 안 가린다. **로컬 통과 / GitHub 404**가 성립한다 |
| 앵커 존재 | 대상 `.md`의 제목을 슬러그화해 대조 (중복 제목은 `-1` 부여) | `#절-이름`이 틀리면 문서 위로 떨어진다 |
| 문서 내 앵커 | 같은 파일 안에서 대조 | 위와 같음 |
| 링크 수집 | 인라인 · **이미지** · **참조 정의**(`[x]: path`) | 인라인만 보면 나머지가 안 보인다 |
| 제외 | 코드 펜스(``` / ~~~)와 인라인 코드 안 | 인용이지 링크가 아니다 |

**대소문자 검사를 넣은 이유는 이 저장소의 전력이다.** 로컬 win32에서 초록인데 CI ubuntu에서 깨진 사례가 이미 있다(`ci-first-run.md`). 링크도 같은 함정을 갖는다.

### 수집 수가 맞는지 교차 확인했다

`35건`이 69개 파일치고 적어 보여 **검사기를 다시 의심했다.** 독립적으로 셌다.

```
$ git ls-files '*.md' | while read f; do grep -o "](" "$f"; done | wc -l
40
```

**40 = 실링크 35 + 펜스 안 5.** 일치한다. 이 저장소는 경로를 대부분 링크가 아니라 백틱 코드로 적기 때문에 링크 자체가 적다.

## 고친 것 — 3건 전부 같은 결함

| 파일 | 전 | 후 |
| --- | --- | --- |
| `archive/2026-08-13/README.en.original.md:3` | `[한국어](README.md)` | `README.original.md` |
| `archive/2026-08-13/README.en.original.md:539` | `[LICENSE](LICENSE)` | `../../../LICENSE` |
| `archive/2026-08-13/README.original.md:534` | `[LICENSE](LICENSE)` | `../../../LICENSE` |

**셋 다 루트에 있을 때는 맞던 상대 경로다.** 두 표지를 `docs/archive/2026-08-13/`로 옮기면서 함께 깨졌고, 옮긴 작업은 그걸 확인하지 않았다.

직전 작업에서 **같은 결함 4건 중 1건만 고쳤다.** 눈에 띈 하나를 고치고 나머지를 찾지 않았기 때문이며, `CLAUDE.md`의 「**전수 조사하고, 무엇을 훑었는지 보고하라**」를 지키지 않은 결과다. P1-50 조사에서 "같은 산출물, 2개 이상의 호출부, 서로 다른 인자" 형태를 전수 조사했던 것과 같은 규율이 필요했다.

본문은 손대지 않았다. **링크 대상만** 고쳤고, 두 보존본 모두 3행에 그 사실을 인용문으로 명시했다.

## 결론

1. **판정 PASS.** 추적 마크다운 69개 파일, 실링크 35건에서 **경로 없음 0 · 대소문자 불일치 0 · 앵커 없음 0**, 색인 **등재 52 = 실측 52**.
2. **직전 문서의 "깨짐 0건"은 거짓이었다.** 실제로 3건이 깨져 있었고, 검사기가 루트 기준 대체 탐색으로 통과시켰다. 3건 모두 고쳤다.
3. **같은 검사기가 이번 세션에 세 번 틀렸다** — 거짓 실패 1회, **거짓 통과 1회**, 범위 부족 1회. 검증하는 것을 검증하지 않으면 이렇게 된다.
