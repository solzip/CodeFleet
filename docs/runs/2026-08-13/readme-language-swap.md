## 무엇을 했나

두 가지다. 둘 다 문서 전용이며, 동결 규칙(`코드는 단 한 줄도 수정하지 않는다`)을 지킨다.

### 1. 기본 표지를 한국어로 되돌렸다

| 파일 | 전 | 후 |
| --- | --- | --- |
| `README.md` | 영문 | **한국어** |
| `README.ko.md` | 한국어 | 삭제 (내용은 `README.md`로) |
| `README.en.md` | (없음) | 영문 |

본문은 한 글자도 바꾸지 않았고, 각 파일 6행의 언어 전환 줄만 새 대상으로 고쳤다.

**`git mv`를 썼지만 git은 이것을 「이름 변경」으로 기록하지 않는다.** 처음에 이 문서는 "`git mv`로 옮겼으므로 이력이 이어진다"고 적었다가 실측 후 지웠다. 실제 값은 이렇다.

```
$ git diff --cached -M --summary
 create mode 100644 README.en.md
 delete mode 100644 README.ko.md          # README.md 는 modify 로만 잡힌다

$ git diff --cached -C --find-copies-harder --summary
 copy README.md => README.en.md (99%)
```

이유는 git의 탐지 방식에 있다. **이름 변경 탐지는 「삭제된 경로」와 「생성된 경로」를 짝짓는다.** 그런데 `README.md`는 삭제되지 않았다 — 경로는 그대로 있고 내용만 영문에서 한국어로 바뀌었다. 짝지을 삭제 쪽이 없으니 영문 본문의 이동은 **복사 탐지(`-C`)를 켜야만** 보인다.

다만 실질적으로 잃는 것은 없다. `README.en.md`는 **예전에 14개 커밋 동안 쓰던 이름으로 돌아온 것**이라(`da3d852`에서 `README.md`로 옮겨 가기 전) 그 이름의 이력이 그대로 이어진다.

```
README.md      [English](README.en.md) | 한국어
README.en.md   English | [한국어](README.md)
```

**부수 효과 — 오래된 문서 3곳이 다시 정확해졌다.** 아래는 원래 이 배치(한국어가 기본)를 전제로 쓰인 문장이고, 영문을 기본으로 바꾸면서 조용히 틀린 상태였다. 이번 스왑으로 손대지 않고 참이 됐다.

| 문서 | 문장 |
| --- | --- |
| `docs/design-progress.md:15` | `README.md  현재 구현 사용법 (한글 기준, 영문은 README.en.md)` |
| `docs/session-handoff.md:28` | `README.md  current implementation usage (Korean; README.en.md is English)` |
| `docs/architecture.md:157` | `+-- README.md / README.en.md` |

### 2. 보존본의 깨진 내부 링크를 해소했다

`docs/archive/2026-08-13/README.original.md` 3행이 `[English](README.en.md)`를 가리켰다. 보존 디렉터리 안에 그 이름의 파일은 없다 — 영문 보존본의 이름은 `README.en.original.md`다.

```diff
- 한국어 | [English](README.en.md)
+ 한국어 | [English](README.en.original.md)
+
+ > 이 파일은 종료 전 루트 README의 보존본이다. 위 링크 대상만 보존본 경로로 고쳤고 본문은 원문 그대로다.
```

**앞선 검토에서는 "보존본이므로 고치지 않는다"고 판단했으나, 그 판단을 뒤집었다.** 근거는 이렇다.

- 링크 **대상**을 고치는 것은 문서가 무엇을 말하는지를 바꾸지 않는다. 원문이 가리키려던 대상(같은 표지의 반대 언어판)을 보존본 경로로 옮겨 **의도를 되살린다.** 본문을 고치는 것과 성질이 다르다
- 죽은 링크를 남기면 보존이 아니라 **결함이다.** 공개 저장소에서 클릭하면 404가 뜬다
- 고쳤다는 사실 자체를 문서 안에 인용문으로 남겼으므로 **되짚을 수 있다** (`CONVENTIONS.md` §7 — 정정은 감추지 않고 기록한다)

## 검증 — 그리고 검증이 잡은 세 가지

루트 표지 2개 + `docs/**` 전 문서를 파싱하는 전수 검사를 돌렸다. **링크만 볼 생각이었는데 세 가지가 더 나왔다.** 셋 다 이 작업이 만든 것이 아니라 **이미 있었는데 보이지 않던 것**이다.

```
INDEX 등재 52 / 실측 52     등재 누락 []   유령 등재 []
실링크 34건 검사, 깨짐 0건
(코드 펜스 안이라 제외한 링크꼴 문자열 4건)
```

### (1) 색인이 문서 한 개를 빠뜨리고 있었다 — 내 앞선 진술이 거짓이었다

`docs/archive/first-thinking.md` (18KB, `c5b7932`, 2026-06-02)가 **색인 어디에도 없었다.**

`INDEX.md`는 스스로 **"`docs/audits/`·`docs/runs/`·`docs/archive/`의 전 문서를 나열한다"**고 선언한다. 그런데 이 파일은 `archive/2026-08-13/` 아래가 아니라 `archive/` 바로 밑에 있었고, **저장소 안 어디에서도 참조되지 않아** 링크를 따라가는 방식으로는 영영 드러나지 않는다.

> **정정 — 앞선 전체 검토의 "INDEX 50행 = 실측 50"은 거짓이었다.**
> 실제로는 **50행 / 51개 파일**이었다. 재귀 순회 대신 좁은 범위를 셌기 때문이고, 이번에 `os.walk`로 다시 재서 드러났다.
> 이 저장소가 P1-50으로 등재한 결함(**산출물이 거짓 문장을 만든다**)과 같은 부류이며, `CLAUDE.md`가 "산문에 적힌 수를 믿지 말고 명령을 돌려 그 수를 읽어라"고 적어 둔 바로 그 자리다. 내가 그 규칙을 어겼다.

색인에 `## 2026-06-02` 절을 만들어 등재했고, 절 아래에 누락 사실을 함께 적었다. 카운트도 `50 → 52`(감사 36 · 실행 9 · 아카이브 7)로 실측값에 맞췄다.

### (2) 링크 검사기가 코드 펜스 안까지 세고 있었다

첫 검사는 **33건 중 1건 깨짐**을 보고했는데, 그 1건은 이 문서 안의 `diff` 블록에 **인용된** 링크였다. 실재하는 링크가 아니라 인용문이다.

**검사기가 틀린 것이지 저장소가 틀린 것이 아니었다.** 펜스 안을 건너뛰도록 고쳐 다시 쟀고, 그래서 위 출력이 **실링크 34건**과 **펜스 안 4건**을 나눠서 보고한다.

이 저장소가 `CLAUDE.md`에 적어 둔 규칙 그대로다 — **"측정하거나 검증하는 것에는 일부러 실패시키는 테스트가 필요하다."** 임시로 짠 검사기라 그 대접을 못 받았고, 첫 판이 틀렸다.

### (3) 검사기가 세는 대상을 함께 보고하게 했다

고친 검사기는 **검사한 링크 수와 제외한 수를 같이 출력한다.** `CLAUDE.md`의 「집합을 훑는 검사는 판정만이 아니라 무엇을 훑었는지 보고해야 한다」에 맞춘 것이다. `0건 깨짐`만 찍는 검사기는 **0건을 검사했을 때도 똑같이 초록**이다.

## 결론

1. 기본 표지가 **한국어**다. `README.md` = 한국어, `README.en.md` = 영문. 본문은 무변경이고 언어 전환 줄만 고쳤다.
2. 보존본의 깨진 링크를 **대상만** 고쳐 해소했다. 최종 **실링크 34건 중 깨짐 0건**.
3. **전수 검사가 이 작업과 무관한 결함 두 개를 더 잡았다** — 색인이 문서 1건을 빠뜨리고 있었고(그래서 내 앞선 "50행 = 50개" 진술이 거짓이었다), 링크 검사기가 코드 펜스 안을 세고 있었다. 둘 다 고쳤고 최종 **등재 52 = 실측 52**다.
4. 실행 코드는 무변경이다. 이 작업으로 CI 실패 8건이나 [미확인] 27건은 하나도 달라지지 않는다.
