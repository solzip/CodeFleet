## 1. 산문 검사 — 주장을 명시적으로 만든다

두 번의 전체 검토가 같은 결론에 닿았다. **숫자는 다 맞는데 그 숫자를 요약한 문장이 틀렸다.** 등재부는 77로 합계가 맞았고, 커버리지도 색인도 맞았다. 틀린 것은 "감사 기록 43편"(실제 48), "미확인 27건은 아무도 들여다보지 않았다"(P1-21은 확인됨) 같은 **문장**이었다.

그리고 **둘 다 사람이 읽어서 찾았다.**

### 방식은 이 저장소가 이미 쓰던 것이다

산문을 긁어 숫자를 추측하지 않는다. `coversRule(ruleId, "조건 인용")`이 그렇듯 **주장을 명시적으로 적게 한다.**

```markdown
- **등재된 결함 77건** — 해소 25, 부분해소 8 ... <!-- fact: registered-findings = 77 --> <!-- fact: findings-resolved = 25 -->
```

HTML 주석이므로 **렌더링 결과는 한 글자도 바뀌지 않는다.** 문장 끝에 붙이므로 목록 구조도 깨지지 않는다.

**선언 34건, 실측 15종, 불일치 0.**

### 네 가지로 실패한다

1. 선언값이 실측과 다르다
2. **아무것도 재지 않는 이름을 선언했다** — 오타가 검사인 척하는 것을 막는다
3. 잰 값을 아무 문서도 선언하지 않았다 → 오류는 아니지만 **이름을 다 찍는다**
4. 선언을 하나도 못 찾았다 → **0건 검사는 통과가 아니다**

3번이 중요하다. "전부 일치"와 "**내가 가리킨 것만** 일치"는 다른 문장이고, 이 체커는 뒤엣것만 말할 수 있다. 선언 안 된 숫자는 여전히 아무도 안 본다.

### 실패 경로를 실측했다

`INDEX.md`의 선언 하나를 55에서 54로 바꿔 돌렸다.

```
######################################################################
#  DOC FACT CHECK FAILED
#  npm test exits non-zero. The report below is context, not a pass.
######################################################################

  mismatches                1
      x  docs/INDEX.md:5: docs-indexed declared 54, measured 55

종료 코드: 1
```

**파일:라인까지 짚는다.** 되돌리자 0으로 복귀했다.

### 상태가 서로를 삼키는 함정

등재부 파싱에서 `부분해소`는 `해소`를 포함하고, `미해소(수용)`은 `미해소`를 포함한다. **짧은 쪽을 먼저 맞추면 합계는 77로 그대로인 채 건수만 엉뚱한 칸으로 간다** — 맞아 보이는 틀린 숫자다. 긴 것부터 맞추도록 했고 테스트가 이 시나리오를 고정한다.

### 만들자마자 두 번 틀렸다

**첫 실행에서 4건이 불일치로 떴고, 그중 둘은 이 체커 자신의 결함이었다.**

| 무엇 | 원인 | 조치 |
| --- | --- | --- |
| `nothing measures a fact named "name"` | **이 체커의 설명 문서에 적은 예시**를 진짜 선언으로 셌다. 코드 인용을 걸러내지 않았다 | 링크 체커의 `stripCode`를 재사용. 테스트 3건 추가 |
| `docs-on-disk declared 56, measured 55` | 새 문서가 아직 **미추적**이라 `git ls-files`가 주지 않았다 | `--others --exclude-standard`로 **커밋 전 문서도** 검사 대상에 넣었다 |

첫 번째는 **링크 체커가 한 시간 전에 저지른 것과 같은 결함이다.** 같은 함정을 다른 파일에서 다시 밟았고, 이번엔 도구가 스스로 잡아 실패로 냈다. 고칠 때 `stripCode`를 다시 짜지 않고 이미 있는 것을 import했다 — 두 번 틀린 자리를 두 벌로 두지 않기 위해서다.

두 번째를 고치면서 **양쪽 체커 모두** 미추적 파일을 보게 됐다. 발행 전에 검사하는 게 발행 후에 검사하는 것보다 낫다. `trackedMarkdown`이라는 이름이 더는 사실이 아니어서 `repositoryMarkdown`으로 바꿨다.

## 2. CLI 가드 — 손으로 만든 URL을 걷어냈다

```diff
- if (process.argv[1] !== undefined && import.meta.url === new URL(`file://${process.argv[1].replace(/\\/g, "/")}`).href) {
+ if (process.argv[1] !== undefined && pathToFileURL(process.argv[1]).href === import.meta.url) {
```

CI windows 실패 2건의 **추정** 원인이다. 가드가 닫히면 체커가 출력 없이 종료 코드 0으로 끝나고, 그것을 자식으로 띄우는 배너 테스트 2건이 깨진다.

**고쳤지만 그것이 CI 실패를 해소했는지는 확인하지 못했다.** 확인하려면 제거한 CI가 필요하다. 로컬 `npm test`는 여전히 0이다.
