## 왜 이 작업을 했나

지시는 하나였다 — 두 README 표지에 종료 사유를 적은 배너를 얹는 것. 이 저장소는 이미
2026-08-13에 동결됐고 「왜 여기서 멈췄나」에 **구조적** 사유 둘이 적혀 있다. 배너가 더하는 것은
그것과 다른 층위의 사유다: **전제가 밖에서 무효화됐다.**

| | 이 프로젝트가 깔고 있던 전제 | 무엇이 무효화했나 |
| --- | --- | --- |
| 1 | worktree 생성·정리를 직접 구현해야 한다 | Claude Code 네이티브 worktree (v2.1.49) |
| 2 | 세션을 관측하려면 PTY 래핑이 필요하다 | 훅 라이프사이클 이벤트 31개 |

이후 기존 구현(agentsd, Bernstein)을 코드 레벨로 조사했고 그 결과 재설계를 보류했다.

## A. 무엇을 고쳤나

`README.md`와 `README.en.md`의 **H1 위**에 같은 내용의 블록인용 배너를 넣었다. 본문은
한 줄도 건드리지 않았다. 두 표지를 함께 고친 것은 직전 커밋(`ea72069`, "say the repository is
closed everywhere a reader enters it")이 세운 기준을 따른 것이다 — 두 표지가 서로 다른 말을
하는 상태를 이 저장소는 결함으로 취급한다.

## B. 배너의 숫자 둘 — 하나는 실측했고 하나는 못 했다

이 저장소의 규칙은 산문의 숫자를 믿지 않는 것이다. 배너에 숫자가 둘 들어가므로 둘 다 따졌다.

**`31`은 실측했다.** 이 머신에 설치된 Claude Code v2.1.234 바이너리가 훅 이벤트 이름을
배열 하나로 갖고 있고, 원소가 정확히 31개다.

```bash
grep -aoE '\[[^][]{0,600}"UserPromptSubmit"[^][]{0,600}\]' ~/.local/bin/claude \
  | sort -u | head -1 | tr ',' '\n' | wc -l
# → 31
```

배열에 `WorktreeCreate`·`WorktreeRemove`가 들어 있다는 것이 전제 1의 무효화도 함께 보인다.
훅이 worktree 수명주기를 이벤트로 내보낸다는 것은 하네스가 그것을 소유한다는 뜻이다.

**`v2.1.49`는 확인하지 못했다.** 공개 CHANGELOG는 `2.1.203` 이전이 잘려 응답에 오지 않는다
(`2.1.234`~`2.1.203`만 수신). 따라서 "네이티브 worktree가 하필 2.1.49에서 왔다"는 부분은
**지시자가 제공한 값을 그대로 옮긴 것이고 이 저장소 안에서는 검증되지 않았다.** 없는 근거를
추정으로 채우지 않는다는 규칙에 따라, 추정하지 않고 여기에 미검증이라고 적는다.

**둘 다 앵커를 붙일 수 없다.** `check-doc-facts.mjs`의 실측 대상 17종은 전부 이 저장소에서
재는 값이다. 남의 바이너리 크기를 재는 실측을 동결된 저장소에 넣는 것은 다른 머신에서
반드시 깨지는 검사를 추가하는 일이다. 그래서 앵커 대신 **기준선을 의도적으로 올렸다** —
`unchecked` 539 → **541**. 늘어난 둘은 두 표지의 `31` 하나씩이다. 버전 문자열은 카운터의
정규식이 `v2.1.49`를 숫자로 세지 않으므로 노출에 잡히지 않는다.

## C. 작업을 시작하자마자 `npm test`가 빨간불이었다 — 배너와 무관한 원인

손대기 전에 잰 값이 **종료 코드 1**이었다. 불일치 3건이고 셋 다 같은 원인이다.

```
x  README.en.md:291: audit-run-records declared 52, measured 53
x  README.md:290:    audit-run-records declared 52, measured 53
x  docs/INDEX.md:5:  docs-on-disk declared 59, measured 60
```

`docs/audits/2026-08-11/fixes/env-DESKTOP-ENGO922.md`(395줄)가 미추적 상태로 트리에 있었다.
검사기는 git이 아니라 **디스크**를 세므로 커밋되지 않은 문서 하나가 세 숫자를 동시에 어긋나게 했다.

여기서 멈춰야 할 이유가 있었다. **이 파일명은 이 저장소가 "존재하지 않는다"고 판정해 둔
이름이다.**

- `docs/audits/2026-08-12/SUMMARY.md:26` — 작업 트리·git 히스토리 전체(`git rev-list --all --objects`)·전문 검색 모두 0건
- `docs/CONVENTIONS.md:79` — 그 사건이 규약 한 조항의 근거다. 없는 문서를 근거로 든 지시를 받았을 때 **내용을 추정해 채우지 않는다**
- `git log --all -- <path>` 를 지금 다시 돌려도 **0건**이다. 이 체크아웃의 히스토리에 그런 개체는 없다

즉 트리에 있는 그 파일은 히스토리가 없는 채로 나중에 나타난 것이고, 출처를 이 저장소 안에서
설명할 수 없다. 그대로 두면 **동결된 판정 셋이 거짓이 된다.** 지시자에게 확인한 뒤
트리 밖(세션 스크래치패드)으로 옮겼다. 지우지 않았다.

옮긴 뒤 위 세 불일치는 사라졌다. **셋 다 이 파일 하나가 원인이었다는 것을 확인하고 옮겼지,
"예상된 실패"라고 넘기지 않았다.**

## E. 두 번째 통과 — 「후속」절이 배너와 반대로 말하고 있었다

첫 통과에서 미해소로 적어 둔 것을 지시자가 바로 고치라고 했다. 배너는 "재설계를 보류했다"고
적는데 같은 문서 「후속」절 마지막 문단은 "제품 정의는 다시 세워 **Warrant**라는 이름으로
**시작했다**", "공개 저장소는 **아직** 없다"고 적고 있었다. **한 문서가 멈췄다와 시작했다를
동시에 말했다.** "아직"은 그 자체로 진행 중을 함의한다.

두 표지의 그 문단만 고쳤다. **시작했다는 사실은 지우지 않았다** — 지우면 "왜 Warrant라는
이름이 여기 있나"가 읽히지 않는다. 시작했고, 그 다음에 멈췄다고 적었다. 사유는 배너와 같은
것을 가리키게 두고 여기서 되풀이하지 않는다.

| | 전 | 후 |
| --- | --- | --- |
| `README.md` | "…이름으로 시작했다 … 공개 저장소는 **아직** 없다" | "…이름으로 시작했다 … **그것도 멈췄다.** … 공개 저장소는 없다" |
| `README.en.md` | "has been reworked and restarted … no public repository **yet**" | "was reworked and restarted … **That stopped too.** … There is no public repository" |

**원 문서를 고친 것이 규약 위반이 아닌 이유.** `docs/CONVENTIONS.md:61`의 "원 문서를 고치지
않는다"는 **등급·상태 판정**에 걸리는 규칙이고, 근거로 붙은 사건 B(`docs/CONVENTIONS.md:65`)도
감사 보고서가 **인용한 시점의 사실**을 보존하는 이야기다. 두 README는 그 부류가 아니라
**현재 진실로 읽히는 살아 있는 문서**이고, 그래서 검사기도 이 둘의 인용을 작업 트리에 대고
검사한다. 직전 커밋 `ea72069`도 같은 이유로 표지를 직접 고쳤다. 첫 통과의 미해소 절에
"새 문서로 적는다"고 쓴 것은 **내가 그 규칙을 너무 넓게 적용한 것이고, 여기서 정정한다.**

이 문서를 새로 만들지 않고 이어 쓴 것도 같은 판단이다 — 덮어쓰기 금지(`docs/CONVENTIONS.md:27`)는
**같은 날 두 번 판정**했을 때 첫 판정이 왜 뒤집혔는지를 남기기 위한 것인데, 여기서 뒤집힌 판정은
없다. 아직 커밋되지 않은 같은 작업의 뒷부분이라 §E로 이어 쓰고 무엇을 왜 바꿨는지 남겼다.

## 결론

두 표지에 종료 사유 배너를 얹고, 배너와 반대로 말하던 「후속」절을 같이 고쳤다(§E). 배너의 숫자 둘 중
`31`은 실측했고 `v2.1.49`는 미검증으로 남겼다. 작업 전 `npm test`가 이미 1이었는데 원인은 배너가 아니라
**"존재하지 않는다"고 판정돼 있던 문서가 트리에 미추적으로 있던 것**이었다 — 옮기고 종료 코드 0을 확인했다.
