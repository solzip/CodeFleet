## 유실 1건 — 이 작업의 성과

**2026-08-11 `06-p0-6-limits.md` 권고 3**:

> **P1** — 타임아웃으로 종료된 Run에 전용 `unavailableReason`(예: `ADAPTER_TIMEOUT`)을 부여해 `runSummaryUnavailableReasons`를 거쳐 리뷰 번들까지 올린다. 지금은 자유 텍스트 stderr 한 줄이 전부라 게이트가 읽을 수 없다.

이 항목은:

- 2026-08-11 SUMMARY.md의 P1 표(P1-12 ~ P1-19)에 **번호를 받지 못했다.**
- `fixes/` 5개 문서의 "범위 밖" 목록 어디에도 **나타나지 않는다.**
- 2단계가 검증 커맨드에는 구현했다 — `VERIFICATION_COMMAND_TIMED_OUT:<commandId>`.
- **어댑터에는 하지 않았고, 그 차이를 기록한 문서가 없다.**

현재 코드로 확인:

```
$ grep -rn "ADAPTER_TIMEOUT\|AGENT_TIMEOUT" src/
(0건)

function toAdapterExecutionStatus(result) {
  if (result.status === "DRY_RUN") return "NOT_EXECUTED";
  if (result.status === "SUCCEEDED") return "COMPLETED";
  if (result.exitCode === null) return "ADAPTER_FAILED";
  return "ADAPTER_FAILED";      // ← 두 갈래가 같은 값으로 수렴
}
```

`resourceLimits.adapter`에도 `timedOut` 필드가 없다. 4단계가 상한과 사용량을 실었지만 "이 프로세스가 그 상한에 걸려 죽었는가"는 싣지 않았다.

**결과**: 리뷰 게이트가 "에이전트가 스스로 죽었다"와 "30분을 넘겨 Harness가 죽였다"를 구분할 수 없다. 후자는 작업이 미완인 채로 잘린 것이고 전자는 아닐 수 있는데, 두 경우 모두 `ADAPTER_FAILED` 하나로 보인다.

**P1-20으로 등재**했다. 고치지 않았다.
