## 판정과 확인 범위

자율 수락을 신뢰하는 파일럿 확대는 NO-GO다. 기존 성공 사례와 자동 테스트만으로 수락·복구의 정확성을 보증할 수 없다. 이번에는 알파 계약·검증·컨트롤러·저장소·원격 전달·프로세스·소스 스냅샷 경로를 읽고, 위험이 큰 경계 3개를 직접 반증했다. 전수 보안 감사나 전체 실패 조합 검증은 아니다. 실제 사용자 코드를 사용하거나 외부 PR을 새로 만들지 않았다.

재현 명령: `node scripts/alpha-quality-audit.mjs` 및 `node scripts/alpha-quality-audit.mjs --docker`. 첫 명령은 실제 컨트롤러와 SQLite에 서비스 오류·저장된 검증 중 상태를 주입하고, 두 번째는 실제 고정 이미지 Docker에서 수행한다. 모델 비용은 발생하지 않는다. defectReproduced가 true이면 제품 결함 재현이며, 테스트 통과가 아니다. 스크립트는 이때 비정상 종료한다.

## AQ-01 — P0: 보호된 검증문 미실행을 성공으로 수락

근거: `src/alpha/verifier.mjs:14`, `src/alpha/verifier.mjs:19`, `src/alpha/contract.mjs:60`.

뺄셈 구현이 덧셈을 반환하면 보호된 테스트는 실제 Docker에서 exit 1, tests 1, fail 1이다. 수정 허용 소스에 `process.exit(0)`을 추가하고 잘못된 계산을 그대로 유지하면 Node는 테스트 파일 자체를 tests 1, pass 1, exit 0으로 보고한다. 기존의 이름 있는 검증문은 실행되지 않는다. 테스트 파일은 수정하지 않았다. 현재 judge는 이 결과를 ACCEPT로 판정한다.

컨테이너 격리 탈출이 아니라 검증 의미의 우회다. 소스가 정상 종료하거나 테스트 등록 흐름에 영향을 주는 경우 수락 근거가 무너진다. 테스트 수만 baseline과 비교해도 이 재현은 전후 모두 1이라 잡히지 않는다. 검증문/테스트 식별성과 실제 실행 완료를 외부에서 관찰하고, 검증 프레임워크에 후보가 영향을 줄 수 있는 범위를 재설계해야 한다. 단순 문자열 process.exit 차단으로 일반 문제를 해결했다고 주장해서는 안 된다.

해제 조건: 조기 종료·검증문 누락·런타임 검증 우회 반증과 정상 수정 대조군을 실제 Docker에서 검증하고, 남는 신뢰 한계를 명시한다. 그 전에는 자동 수락을 신뢰하지 않으며 독립적으로 변경을 검토한다.

## AQ-02 — P1: 공급자 오류 시 비용 불확실성 누락

근거: `src/alpha/controller.mjs:39`, `src/alpha/controller.mjs:84`, `src/alpha/controller.mjs:86`, `src/alpha/controller.mjs:124`.

propose가 호출 후 transport 오류를 던지도록 주입했다. 결과는 WAITING_HUMAN, attempts 1, reportedCostUsd 0, unknownCostAttempts 0이다. 실제 비용을 알 수 없는데도 불확실한 시도 카운터는 증가하지 않는다. worker가 GENERATING 상태에서 사라지는 경우의 복구 로직은 있으나 일반 오류 catch는 상태를 바꾸므로 그 경로를 타지 않는다. 실제 공급자가 청구했다는 실험은 아니며, 관측할 수 없는 비용을 표현하지 못한 결함이다.

해제 조건: 호출 예약·응답 비용 확정·불확실 상태를 원자적으로 기록하고, timeout·오류·취소·worker 종료를 중복 집계 없이 검증한다.

## AQ-03 — P1: 마지막 제안의 검증 복구가 예산에 막힘

근거: `src/alpha/controller.mjs:80`, `src/alpha/controller.mjs:119`.

maxAttempts 1, attempts 1, 유효한 이전 제안과 실패 baseline을 가진 VERIFYING 체크포인트를 주입해 재개했다. 컨트롤러는 저장된 제안을 읽지만 검증을 재개하지 않고 Attempt budget exhausted로 WAITING_HUMAN이 된다. 새 모델 호출 없이 완료할 수 있는 검증도 시도 예산 때문에 막힌다. 실제 프로세스 kill 재현이 아니라 해당 persisted state에서의 실행 재현이다.

해제 조건: 모델 시도 예약과 검증 재개 상태를 분리한다. 마지막 시도의 VERIFYING 복구는 추가 모델 호출·추가 과금 없이 기존 제안을 검증해야 한다.
