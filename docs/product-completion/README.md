# CodeFleet 공식 제품 문서

현재 제품 정의·구조·상태·다음 작업의 문서 지도다. 설계·오프라인 구현·실제 Host 수용·공개 패키지의 지원 범위를 구분한다.

## 목표

CodeFleet은 **기존 Codex CLI·Claude Code의 모델·인증·세션을 활용하는 Host-Native AI 개발 오케스트레이션 확장 도구**다. 자연어 목표를 Task Draft·Validator·Workflow/DAG로 연결하고, 단일 Agent를 기본으로 필요시 역할을 나눈다. Policy·Capability·승인·상태·복구를 관리하며 AI의 성공 주장과 독립 Evidence·Judge의 완료 판정을 구분한다.

기본 계획·DAG 준비에는 Docker·WSL·별도 OS 계정·직접 모델 API Key가 필요 없다. Docker는 선택적 보호 검증 Backend다. Local Verification은 Protected Verification과 다르며 Host Sandbox는 미검증이다. 실제 Host Live·자동 위임 상태는 진행 현황을 따른다. 신규 프로젝트 Bootstrap과 기존 프로젝트 개선이 제품 목표이며, Git HEAD 없는 Bootstrap은 별도 개발 중으로 현재 main의 완료 기능이 아니다.

사용자는 방향, 권한, 예산, 완료 기준을 정한다. 시스템은 허용된 작업을 진행하고 근거를 남긴다. 사용자는 진행 상황을 감독하고 중단하거나 예외를 결정한다. 사람의 개입 시간 감소와 결과 품질을 함께 측정한다.

## 적용 범위와 기존 문서 관계

- 사용자가 이번 대화에서 명시한 **제품 완성·공개·실사용**을 새 계획의 목표로 삼는다.
- 기존 아카이브 문서는 당시 제품과 실측의 역사다. 과거 실패·제약·판정을 새 계획으로 덮어쓰지 않는다.
- 기존 `FINAL RULE`은 기존 구현의 기준이다. 새 자동 진행·위임·반영 정책은 구현 전에 별도 규칙과 회귀 시나리오로 정의한다. 이 문서만으로 기존 실행 정책이 변경되지는 않는다.
- 각 문서는 현재 구조, 구현 상태, 사용 안내 또는 당시 계획이라는 책임을 갖는다. main 통합만으로 공개 패키지에 포함됐다고 주장하지 않는다.
- 제품 작업명은 CodeFleet을 유지한다. 기존 README가 언급한 Warrant와의 통합·이관 여부는 결정 전이며, 그 프로젝트의 구현은 이번 검토에 포함하지 않았다.
- 권리자가 MIT 전환을 승인했다. 현재 LICENSE는 실행·수정·배포·상업적 사용을 허용한다. 과거 사용 금지 정책은 당시 기록으로 남기며, 제품 완성·품질 보증과 사용 허용을 구분한다.

## 첫 출시 범위

이 절은 초기 Alpha 출시 범위의 기록이다. 현재 Host-Native 범위는 위 목표와 제품 원칙, 다음 완료 기준은 로드맵을 따른다. 아래 후속 항목은 당시 출시 제한이며 이후 구현·검증을 부정하는 현재 상태표가 아니다.

대상 사용자는 자신의 저장소를 관리하는 개인 개발자와 소규모 팀의 담당자다. 하나의 프로젝트에서 명확한 완료 기준을 가진 저위험 버그 수정·작은 기능 변경을 처리한다.

포함: 환경 진단, 작업 계약, 정책 위임, 격리 실행, 독립 검증, 제한된 재시도, 영속 상태, 예외 보고, PR 생성, 비용·시간 측정, 설치·제거·업데이트 안내.

후속: 다중 사용자 서버, 동시 에이전트 편집, 자동 병합·배포, 회사 전체 업무 커넥터, 복잡한 자동 기획, 별도 웹 대시보드. 첫 출시에는 필수로 넣지 않는다.

## 완료의 의미

코드가 존재하는 것, 테스트가 통과하는 것, 외부 사용자가 쓸 수 있는 것을 구분한다. 첫 공개 사용 릴리스는 [로드맵](roadmap.md)의 설치·기능·실패 복구·품질·공개 준비 게이트를 모두 충족해야 한다.

`M0-T1`에서 시작한 실행 결과와 다음 작업은 [진행 현황](progress.md)에서 확인한다. 원래의 광범위한 계획과 현재 제한된 알파 경로를 구분한다.
