# 진행 현황과 결정 목록

갱신일: 2026-09-30. 현재 단계: 계획 문서화 완료, M0 구현·실행 착수 전.

## 현재 상태

사용자의 확정 목표는 제품 완성, 공개 저장소, 실제 사용자 사용이다. [아키텍처](architecture.md)와 [로드맵](roadmap.md)의 기술 선택·출시 범위는 작업 초안이다. 새 제품 코드, 새로운 제품 실행 측정, 원격 저장소 생성·공개, 라이선스 변경은 아직 수행하지 않았다.

| 단계 | 상태 | 근거 |
| --- | --- | --- |
| 종합 검토·아키텍처·로드맵 문서화 | DOCUMENTED | [이번 작업 기록](../runs/2026-09-30/product-completion-planning.md) |
| M0 기준선·범위 확정 | TODO | 현재 실행 결과 없음 |
| M1 신뢰할 수 있는 한 작업 | TODO | 새 구조의 실행 근거 없음 |
| M2 자율 루프·복구 | TODO | 새 루프의 실행 근거 없음 |
| M3 PR 전달 | TODO | 통합 전달·재조정 근거 없음 |
| M4 공개 알파·파일럿 | TODO | 외부 사용자·패키지 배포 근거 없음 |
| M5 공개 사용 릴리스 | TODO | 출시 게이트 미평가 |

상태 정의: TODO → IN_PROGRESS → IMPLEMENTED → VERIFIED. 막히면 BLOCKED와 원인·해제 조건을 기록한다. DOCUMENTED는 설계 산출물에만 사용하며 구현 완료로 집계하지 않는다.

## 결정 목록

| ID | 내용 | 상태 | 결정 시점·영향 |
| --- | --- | --- | --- |
| D01 | 공개하여 실제 사용자가 사용하는 제품 완성 | 사용자 확정 | 전체 목표 |
| D02 | 첫 범위는 단일 운영자의 저위험 개발 작업→PR | 제안 기본안 | M0에서 수락 조건 고정 |
| D03 | 첫 릴리스 자동 병합·배포 제외 | 제안 기본안 | 권한·검증 범위 |
| D04 | 기존 저장소 재개 또는 후속 저장소 이관 | 미결정 | M0-T3. 기존 아카이브와 Warrant 관계 확인 |
| D05 | 사용을 허용하는 라이선스·권리 범위 | 미결정 | 공개 사용 릴리스 전 필수. 현재 LICENSE 유지 |
| D06 | 첫 지원 OS·어댑터 조합 | 미결정 | M0-T2 실측으로 선정. 현재 개발 환경 우선 |
| D07 | SQLite 상태 저장소·아티팩트 파일 분리 | 제안 기본안 | M0 호환성 검증, M1 최소 구현 |
| D08 | 공개 저장소 소유자·이름·패키지 배포 경로 | 미결정 | 원격 생성·게시 전에 확정 |
| D09 | 파일럿 목표와 참여자 모집 | 제안 기본안 | M4 전 확정. 개인·회사 저장소 동의와 비밀 경계 확인 |

미결정 항목은 관련 작업 직전에 해소한다. 현재 문서 작성과 M0의 읽기 전용 현 상태 조사까지 막는 항목은 아니다. 정책·라이선스·외부 게시 변경은 별도 구체 변경으로 검토한다.

## 다음 작업 패킷

**M0-T1 — 현재 실행 기준선 확보**

- 입력: 현재 커밋, 기존 실행 기록, R01/R03/R05, 지원 후보 환경.
- 작업: 전체 기존 검사 종료 코드 확보 → 환경·도구 버전 기록 → 작은 실제 저장소 작업 한 건 선정 → 계약부터 결과 전달까지 현재 흐름 재현 → 우회·실패·관측 불가 구분.
- 출력: 환경 표, 실행 명령·종료 코드, 산출물 경로·해시, 실패 분류, M1의 첫 슬라이스 제안.
- 제외: 정책 우회로 성공 만들기, 과거 테스트 수를 새 실행으로 인용, 새 원격 게시.
- 완료 조건: 다른 세션이 같은 환경에서 재현할 수 있는 기록. 실패해도 기준선 조사는 완료할 수 있으나 제품 게이트 통과와는 다름.

## 갱신 방법

각 작업이 끝나면 아래 양식으로 새 실행 기록을 만들고 해당 단계 상태와 링크만 갱신한다.

```text
작업 ID / 대상 커밋 / 환경 / 요구 ID
변경한 동작 / 수락 조건
실행 명령 / 종료 코드 / 확인한 범위
산출물 / 관측 한계 / 잔여 결함
다음 작업 / 필요한 결정
```

## 위험 추적

| 위험 | 대응 | 해제 증거 |
| --- | --- | --- |
| 설계가 구현보다 앞서감 | 한 수직 슬라이스씩 구현·반증·기록 | 단계별 실제 실행 |
| 검증 비용 때문에 무분별한 면제 | gap과 defect 구분, 자동 수락 기준 유지 | 부정 사례 거부 |
| OS·어댑터 범위를 과도하게 확대 | 첫 지원 조합 제한 | 지원 매트릭스 |
| 사람의 수고가 계약 작성으로 이동 | 준비·질문·확인까지 개입 시간에 포함 | 파일럿 비교 |
| 공개했지만 설치·유지가 어려움 | 깨끗한 환경 설치·이슈 대응 준비 | 외부 사용자 완주 |
| 과거 상태와 현재 상태 혼동 | 이 문서를 현재 진행의 단일 출처로 사용 | 근거 링크와 상태 일치 |
